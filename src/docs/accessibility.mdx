# Accessibility

Every component is built against the relevant [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) pattern and targets **WCAG 2.1 AA** as a practical baseline — not an afterthought bolted on at the end.

---

## How it's enforced, not just claimed

This isn't a documentation promise with nothing behind it:

- Every story runs through **axe-core** via Storybook's `addon-a11y`, configured in
  `.storybook/preview.tsx` with `a11y.test: 'error'` — a real accessibility violation
  **fails the Storybook build**, the same as a TypeScript error would.
- `npm run test:storybook` runs those same axe checks headlessly in CI
  (`test-storybook` job), on every push and pull request.
- Keyboard interaction (arrow keys, `Home`/`End`, `Escape`, focus trapping) is covered
  by dedicated tests in each component's `*.test.tsx`, not just visual review.

---

## Try it yourself

Open **any** component's story in this Storybook and look at the **Accessibility**
tab in the addon panel below the canvas. It runs the exact same axe-core scan CI
runs, live, against whatever variant/args you currently have selected — violations,
passes and incomplete checks are all listed with the specific DOM node and WCAG
criterion involved.

This is the fastest way to confirm a component is accessible for *your* specific
combination of props, not just the default story.

## Known trade-offs

A couple of deliberate, documented decisions worth knowing about rather than
discovering by surprise:

- **`DropdownMenu` doesn't cycle `Tab` inside the menu.** Combining roving-tabindex
  arrow-key navigation with Floating UI's focus manager in a way that also passes
  axe's `aria-hidden-focus` check meant disabling the focus guards that would
  otherwise let `Tab` wrap around inside the menu. Arrow keys, `Home`/`End` and
  `Escape` all work as expected; `Tab` simply moves focus out of the menu like it
  would for any other control.
- **`Alert`'s `autoDismiss` is opt-in and off by default.** An alert that disappears
  on its own without user input can conflict with [WCAG 2.2.1 (Timing
  Adjustable)](https://www.w3.org/WAI/WCAG21/Understanding/timing-adjustable.html).
  Use `dismissible` (a manual close button) for anything the user must be able to
  read on their own schedule.
